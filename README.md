# 文字冒险：营地与森林（终端版）

Node.js 22+，纯命令行客户端，无网页、无图片。单人也启动服务器，再由客户端自动连接；多人共用服务器权威逻辑。世界暂不存档。

## 配置内容

物品、装备、技能和地图已迁移到 `config/`，编辑 JSON 后重启生效，无需修改或重新编译 TypeScript。

- `config/items.json`：装备、消耗品、材料、货币。
- `config/skills.json`：技能消耗与效果。
- `config/world.json`：地图出口、地面物品、出生位置和敌方编组/数量。
- `config/enemies.json`：敌人种类、生命、攻防、技能和行动规则。
- `config/player.json`：初始背包、装备、技能和属性。

完整字段与新增示例见 [配置说明](config/README.md)。可用 `npm run config:check` 检查配置；联机客户端会自动同步服务器配置。

## 启动

```sh
npm install
npm start
```

启动后自动生成随机昵称并进入单窗口分区 TUI：左上角色状态、右上字符地图、左下命令记录与执行结果、右下事件与聊天，底部固定输入行。各区域只更新变化的行，不再清屏重画，也不推动整个终端滚动；事件不会打断正在输入的命令。建议至少 80 列、24 行，最小 60 列、22 行；窗口过小时会显示放大提示。

- 输入「背包」（或 `bag` / `inventory`）打开左下背包视图；输入「关闭背包」或按 `Esc` 恢复命令记录。背包平时隐藏，打开时仍可输入命令，拾取后实时更新。
- `Tab` 切换左右下方区域，`PgUp` / `PgDn` 翻阅记录或背包；背包每页容量随窗口高度变化。Mac 可使用 `Fn+↑` / `Fn+↓`。
- 角色显示生命值、法力值、饱食度、水分值，服务器初始值均为 100，上限为 100；当前不自动消耗，木桩不会反击，技能会消耗法力，暂未增加进食或饮水机制。
- `↑` / `↓` 调用历史命令，左右键、Home/End、退格和 Delete 编辑输入。
- 查看历史时保留阅读位置，翻回底部后跟随最新消息。
- `Ctrl+C` 或「退出」结束客户端并恢复原终端。
- 非交互管道使用普通文字输出，便于自动测试。

默认无需输入昵称，例如自动生成「晨雾旅人-a1b2c3」。也可手动指定昵称：

```sh
npm start -- --name 旅人
```

## 命令

```text
前往 森林
查看
拾取 金币
拾取 石头
背包
关闭背包
前往 营地
说 大家好
帮助
退出
```

也支持 `go forest`、`go camp`、`look`、`pickup coin`、`say hello`、`help`、`quit`。「查看」列出当前位置的地面物品、ID 和数量；「拾取 物品名」或「pickup 物品ID」选择目标，不指定目标会显示用法，不会自动拾取。进入地点时也会自动介绍可见物品。森林中有金币和石头，持有物品通过「背包」命令查看。服务器判定物品归属，两个玩家不能重复领取同一件物品。

## 多个终端窗口，共享一个角色

主窗口底部显示一个本机会话连接码，例如 `54321:一串32位字符`。复制实际连接码，在新终端切换到本项目目录，执行：

```sh
npm run view -- --attach 你的连接码 --view status
npm run view -- --attach 你的连接码 --view inventory
npm run view -- --attach 你的连接码 --view map
npm run view -- --attach 你的连接码 --view events
npm run view -- --attach 你的连接码 --view commands
```

分别打开角色、背包、地图、事件、命令窗口。`--view all` 为默认四区界面。窗口由你自行打开和排列，不依赖特定操作系统的窗口管理功能。这是保留的可选功能，默认使用单窗口分区界面。

这些窗口附着到同一个主客户端，只建立一个游戏角色。关闭附加窗口不会退出角色；在命令窗口输入「退出」仅关闭该窗口。关闭主客户端会结束整个角色会话及所有附加窗口。主客户端自建的服务器也会关闭；需要独立服务器常驻时使用下方独立启动方式。

连接码只用于本机，不用于朋友入服，每次主客户端启动都会变化，请勿分享。主客户端必须持续运行。

## 多人

房主启动服务器并加入：

```sh
npm run multi -- --name 房主
```

终端事件区域会列出可供好友连接的局域网地址。好友在自己的电脑准备项目并安装依赖后执行（替换 IP）：

```sh
npm run client -- ws://192.168.1.2:3000/ws --name 好友
```

好友的主客户端也可以开启自己的附加窗口。每位玩家应使用不同昵称。

独立服务器，不启动玩家客户端：

```sh
npm run server
```

房主和好友都使用 `npm run client -- ws://服务器IP:3000/ws --name 昵称` 连接。关闭玩家客户端不会关闭独立服务器。

默认单人只监听本机，多人监听所有网卡。局域网需要同网及防火墙允许端口；公网需要可访问地址和端口映射，不提供内网穿透或登录认证。自定义端口（macOS / Linux）：`PORT=3100 npm run multi`。默认端口已占用时请更换端口或连接已运行的服务器。

## 生命周期

`Ctrl+C` 或「退出」结束当前客户端；独立服务器使用 `Ctrl+C` 关闭。玩家离线后角色移除，重进创建新角色；已被领取的金币不会因玩家离线而恢复。服务器重启后世界重置。突然断网的玩家通过心跳清理。

## 开发与测试

```sh
npm run build
npm test
```

- `src/game.ts`：世界规则。
- `src/server.ts`：WebSocket 游戏服务器与 HTTP `/health` 检查。
- `src/cli.ts`：终端交互、本机会话中继、单人启动与远程连接。
- `src/terminal.ts`：命令解析和普通文字视图。
- `src/tui.ts`：固定分区、局部刷新、输入编辑和独立历史视口。
- `tests/`：真实双客户端同步、竞争领取、命令行进程、附加会话和退出测试。

编译后可运行 `node dist/cli.js`，独立服务器运行 `node dist/server.js --multiplayer`；运行目录必须保留 `config/`。

## 双击启动（macOS）

在 Finder 双击项目里的 `启动游戏.command`，即可用随机昵称进入单窗口分区界面，不再自动打开附加窗口。首次运行会在缺少依赖时执行 `npm install`。

```sh
npm start
npm run multi -- --name 房主
npm run client -- ws://192.168.1.2:3000/ws --name 好友
```

旧命令 `npm run panels` 保留为单窗口启动别名。附加视图仍可按前文手动启动，但不再是默认使用方式。


## 木桩战斗测试

敌人定义中只有一种「木桩」，营地通过编组放置2只。地图显示「木桩 ×2」，战斗中自动区分「木桩 A」「木桩 B」。攻击木桩都会进入经典的一对二战斗界面：上方居中展示两个敌人，中间是独立战斗消息框，下方为指令菜单与队伍状态。战斗时暂时隐藏探索地图和聊天区域，消息仍会接收，退出战斗后可在事件记录查看。保留普通细线边框。

```text
攻击 木桩
目标 2
攻击
1
防御
战斗
脱离战斗
```

- 第一次「攻击 木桩」进入战斗，入场消息自动逐条播放，然后停在第 1 回合。
- 方向键选择「攻击／技能／道具／装备／防御／逃跑」，空格确认。选择攻击后，左右键或 `1` / `2` 选敌，空格才真正出手，Esc 返回行动菜单。
- 行动结果按「玩家行动 → 木桩 A行动 → 木桩 B行动 → 下一玩家回合」逐条自动显示，每条约 1.1 秒，无需手动继续。播报期间不能重复提交行动；正在行动的敌人会单独标记。消息框累积显示最近的多条结果，不会被下一条覆盖，PgUp/PgDn 可翻阅本场战斗已播出的历史（最多保留 500 条），翻阅时新消息不会打断阅读位置。
- 战斗中默认使用菜单；需要旧文字命令时，按 `/` 切入文字输入，再输入下列指令；Esc 可取消输入。所有菜单选项统一用空格确认，Enter 仅提交文字命令。
- 「目标 1」「目标 2」或直接输入 `1` / `2` 选择敌人；也可使用「目标 木桩 B」或 `target dummy-2`。选择目标不消耗回合。
- 「攻击」对当前选中目标造成装备与增益共同计算的物理伤害（初始木剑为 10）；「攻击 木桩 B」可在行动时直接指定另一个参战目标。
- 「防御」消耗本回合进行防御。木桩不会造成伤害，当前不增加额外减伤数值。
- 玩家攻击或防御后，按木桩 A → 木桩 B 的顺序各自执行一次「一动不动，没有反击」，然后进入下一玩家回合。服务器统一结算敌方行动，客户端按节奏逐条自动展示。
- 「战斗」查看双方、目标、回合和累计伤害；「脱离战斗」返回探索界面。移动离开营地也会结束练习。

木桩生命始终为 ∞，不会死亡，无奖励；受击次数及伤害统计由服务器维护。不同玩家有独立练习遭遇与回合，共享木桩的受击统计，旁观者不会被强制切入战斗。断线移除角色和练习状态，服务器重启清空统计。


## 装备、技能和药水

新角色自带测试包：全部测试装备各 1 件、每种药水各 3 瓶，已学习全部 4 个技能。初始装备为木剑、布衣、皮帽，饰品位空置。背包保留装备本体，装备位引用物品，换装不会额外生成物品。角色属性显示攻击、防御和魔法强度。

| 装备位 | 可用物品 |
| --- | --- |
| 武器 | 木剑（攻击10）、铁剑（攻击16）、法杖（攻击8，魔法+10） |
| 护甲 | 布衣（防御+2）、锁甲（防御+6） |
| 头盔 | 皮帽（防御+1）、铁盔（防御+3） |
| 饰品 | 力量戒指（攻击+4）、魔力护符（魔法+8）、守护护符（防御+4） |

战斗菜单采用两列三行排列：攻击／技能、道具／装备、防御／逃跑。方向键选择，空格确认。技能、道具和装备子列表用上下键选择、空格确认、Esc 返回；列表超过四项会自动翻页，底部显示选中物品的效果。单体技能还需选择敌人并用空格确认，群体技能和自身治疗无需选敌。

**战斗中攻击、施放技能、使用药水、更换或卸下任何装备均消耗 1 回合**，然后两个木桩依次行动。打开列表、查看说明、选择目标、取消操作均不耗回合。未持有、已装备、法力不足、属性全满等失败情况不扣数量、不扣法力、不消耗回合。非战斗换装和恢复药水不会触发战斗回合。

| 技能 | 法力 | 效果 |
| --- | --- | --- |
| 重击 | 8 | 单体物理伤害：攻击 ×2 |
| 火球 | 12 | 单体魔法伤害：30+魔法强度 |
| 横扫 | 15 | 每个敌人各受到攻击 ×0.8 的物理伤害，向下取整 |
| 治疗 | 10 | 恢复自身生命35，上限100 |

药水包含：生命药水（+40生命）、大生命药水（+80生命）、法力药水（+35法力）、复合药水（生命及法力各+25）、面包（+40饱食）、饮用水（+40水分）、力量药水（攻击+8）、魔力药水（魔法+10）、再生药水（每次行动后恢复生命10）。恢复不超过100，药水只能对自己使用。

三种增益药水仅限战斗使用，持续后续3次自身行动，喝药当次不扣新效果的次数；同类效果刷新、不叠加，不同效果可共存。攻击、防御、技能、换装和使用其他道具都会推进已有增益次数。战斗结束或离开地点会清除增益。木桩仍不反击。前往森林攻击「森林鼠」可测试普攻、技能反击、防御与护甲减伤、敌人死亡和战斗胜负。

也可以使用文字命令（战斗中先按 `/`）：

```text
装备
装备 铁剑
装备 锁甲
装备 铁盔
装备 力量戒指
卸下 饰品
技能
施放 火球 木桩 B
施放 横扫
施放 治疗
药水
使用 法力药水
使用 力量药水
```

`装备` / `技能` / `药水` 不带参数时显示列表。英文指令支持 `equip`、`unequip`、`cast`、`use`（对应物品或技能 ID），中文名称也可用于英文指令，例如 `use 法力药水`。


## 普通敌人与胜负

`config/enemies.json` 定义敌人种类，不重复定义同种敌人的 A/B 实例。地图的 `encounters[].members` 用 `enemyId` 和 `count` 引用定义。相同编组一起参战，同名实例在战斗中自动加 A/B/C 后缀，地图只显示基础名称和数量。详细字段和示例见 [敌人配置说明](config/README.md#5-敌人定义enemiesjson)。

默认营地仍是2只无限生命木桩，森林放置1只「森林鼠」测试正常战斗。普通敌人可以普攻、用技能、防御、待机，支持循环和条件优先级规则。法力不足或不满足条件时使用后备行动；生命归零后不能再选中、行动或被重复击杀。所有敌人倒下即胜利，不再执行反击；玩家倒下即失败，停止剩余敌人行动。

胜负播报结束后自动返回探索。测试版失败无掉落惩罚，回出生点恢复初始属性，装备和背包保留。普通敌人的生命、法力及死亡状态保存在本次服务器内存中，重启重置，当前没有自动刷新或经验奖励，尸体支持搜刮和分解。正常战斗编组一次由一名玩家交战，逃跑、离开、结算或断线会释放占用；无限生命且只待机的木桩编组仍允许多人独立练习。


## 搜刮与分解

击败森林鼠并结束战斗播报后，可输入：

```text
搜刮 森林鼠
拿取 金币 2
全部拿取
关闭搜刮
分解 森林鼠
查看
拾取 生肉
```

搜刮会在命令区域打开尸体背包，用方向键选择、空格确认，Esc 关闭。每只敌人的战利品在生成时随机确定，反复搜刮不会刷新；拿空后尸体仍保留。分解会移除尸体，将固定生物资源及未拿走的战利品散落到地面，不会直接放入玩家背包。打开尸体时也可直接输入 `分解`。

默认森林鼠固定分解出2份生肉和1份骨头，背包有概率生成金币和生命药水。修改 `config/enemies.json` 的 `loot` / `resources` 即可调整，详见 [配置说明](config/README.md)。尸体是多人共享容器，同步拿取和分解不会重复产生物品；重启服务器会重置世界。
